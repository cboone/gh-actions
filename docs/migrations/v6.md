# v6 Migration Guide

The v6 release changes where `scan-for-secrets.yml` reads Gitleaks rules on pull
requests and how the workflow and standalone actions report findings. Update
your `uses:` references after reviewing the changes that apply to your scans.

## Gitleaks pull requests use the base revision's rules and ignores

On `pull_request`, `scan-for-secrets.yml` still scans the event checkout. It
reads `allowlist-config` from the exact base revision. With that input unset,
it uses the base's `.gitleaks.toml` or the built-in rules. It also uses the
base's `.gitleaksignore`, with an empty fallback. Other events read these files
from the scanned checkout.

Merge reviewed rule and ignore changes into the target branch before relying on
them in a later pull request. If you set `allowlist-config`, merge that file
into the target branch before pointing the workflow at it. A missing explicit
config fails the scan.

The config, its extensions and symlink targets must stay within the base
checkout, relative extension paths resolve from the base repository root, and
duplicate case-insensitive keys fail validation.
[Scan workflow reference][scan-workflow]

## Reusable scans that require GitHub.com workflow context

Both TruffleHog paths now need `job.workflow_repository` and `job.workflow_sha`
to fetch the checker, including the default path with `trufflehog-allowlist`
unset. The Gitleaks pull-request path also needs these fields to fetch its
helpers. GitHub.com supplies the fields automatically.

On GitHub Enterprise Server, use the standalone actions in regular jobs and
install `jq` on the runner for either action. Translate `scan-scope` to `args`,
with each argument on its own line. The paths below assume `.` is the event
checkout. Fetch the full history for `full-history`.

| `scan-scope`   | `run-gitleaks`               | `run-trufflehog`           |
| -------------- | ---------------------------- | -------------------------- |
| `full-history` | `detect --source .`          | `git file://.`             |
| `working-tree` | `detect --source . --no-git` | `filesystem --directory .` |

Pass the workflow's `trufflehog-allowlist` path as the standalone
`run-trufflehog` action's `allowlist` input.
[TruffleHog action reference](../../actions/run-trufflehog/README.md)

For Gitleaks pull-request scans, use the base revision's config and ignore
file for `--config` and `--gitleaks-ignore-path`. Use the workflow's helper to
prepare these files from a separate checkout of the exact base revision and
write them outside the event checkout. The helper supplies the built-in rules
if both `allowlist-config` and the base `.gitleaks.toml` are absent. It supplies
an empty ignore file if the base lacks `.gitleaksignore`.
[Config preparation helper](../../scripts/prepare-gitleaks-config.py)

Gitleaks also loads `.gitleaksignore` from the scan source, so move any proposed
file or symlink outside the event checkout before scanning the repository,
then restore it even if the scan fails. In `working-tree` mode, first scan a
proposed regular `.gitleaksignore` separately with
`detect --source .gitleaksignore --no-git` and the same base config and ignore
arguments. Keep that scan's failure in the job result.
[Scan workflow reference][scan-workflow]

## Scan logs contain finding metadata

In `scan-for-secrets.yml`, Gitleaks logs the fingerprint, file, line and rule.
TruffleHog logs the detector, verification state, commit, path and line. The
standalone actions log the same fields for their respective scanners, and
`run-trufflehog` also logs the source type and any available location fields
for sources other than Git and Filesystem. Update log parsers for both the
workflow and the standalone actions to consume finding metadata. Use the job
result for the workflow and the action step result for standalone scans to
determine whether a scan failed. Scanner diagnostics stay private.

## `run-gitleaks` requires `jq` and controls reporting

Make `jq` available before calling the action. Remove `--report-path` (`-r`),
`--report-format` (`-f`), `--report-template`, `--diagnostics` and
`--diagnostics-dir` from `args`. Drop custom redaction settings or use `--redact`
or `--redact=100`. The action applies full redaction and preserves ordinary
scan arguments and caller-selected exit codes.

Supply `args` only from trusted sources. If you need a separate report or
diagnostic output, run the Gitleaks binary directly and keep that output out of
logs and artifacts.

## `run-trufflehog` requires `jq` and controls output

Make `jq` available even if you omit `allowlist`. Remove `-j`, `--json` and
`--no-json` from `args` because the action sets JSON output itself. Remove
`--json-legacy`, `--sarif`, `--github-actions` and `--output-report` because
the action rejects them.

Supply `args` only from trusted sources. The action passes `@file` arguments
through without checking the options in those files. Review those files for
output options and keep any reports they enable out of logs and artifacts.

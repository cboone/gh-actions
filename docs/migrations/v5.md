# v5 Migration Guide

The v5 release hardens how the npm workflows install dependencies, and adds
`publish-to-npm-with-oidc.yml` for publishing to npmjs.com with no stored
credential.

Two defaults changed, both in `publish-to-npm.yml` and `deploy-to-pages.yml`.
Callers that commit a lockfile and need no lifecycle scripts during install need
no change.

## A lockfile is now required

Before, a repository without `package-lock.json` or `npm-shrinkwrap.json`
installed with `npm install`, which resolves versions at run time. That made the
registry the only thing standing between a fresh resolution and a publish or a
deployment. Now the job fails instead, with:

```text
No lockfile found. Commit package-lock.json, or set allow-npm-install: true.
```

Two ways forward. Commit a lockfile, which is the reason the default changed:

```bash
npm install --package-lock-only
git add package-lock.json
```

Or keep the old behavior explicitly:

```yaml
jobs:
  publish:
    uses: cboone/gh-actions/.github/workflows/publish-to-npm.yml@v5.0.0
    with:
      allow-npm-install: true
    secrets:
      NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

The fallback now also logs a warning saying versions were resolved at run time,
which it did silently before.

## Dependency lifecycle scripts no longer run

Installs pass `--ignore-scripts`, so a dependency's `preinstall`, `install` and
`postinstall` scripts no longer execute in a job that publishes or deploys. A
build that genuinely needs them, such as one whose dependency compiles a native
binding on install, sets:

```yaml
with:
  run-install-scripts: true
```

This does not affect the package's own publish lifecycle: `npm publish` still
runs `prepublishOnly`, `prepack` and `prepare` as it always has.

## Publish jobs no longer restore an npm cache

`publish-to-npm.yml` sets `package-manager-cache: false` on `setup-node`. No
caller change is needed. Expect a publish to spend a little longer installing,
in exchange for a cache entry written by another job being unable to influence
what gets published. `deploy-to-pages.yml` builds rather than publishes and
keeps its cache.

## Optional: move a publish to trusted publishing

For a package on npmjs.com, `publish-to-npm-with-oidc.yml` removes the
publishing token entirely and adds provenance attestations. It is a separate
workflow rather than an input on `publish-to-npm.yml`, because a caller must
grant every permission the workflow it calls declares, and a token-path caller
should not have to grant `id-token: write`.

```yaml
jobs:
  publish:
    permissions:
      contents: read
      id-token: write
    uses: cboone/gh-actions/.github/workflows/publish-to-npm-with-oidc.yml@v5.0.0
```

Configure the trusted publisher on npmjs.com first, naming your repository and
the filename of the workflow that calls this one. See
[docs/workflows/publish-to-npm-with-oidc.md](../workflows/publish-to-npm-with-oidc.md)
for the fields and the version requirements.
